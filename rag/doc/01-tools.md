# 01. Выбор инструментов

Фаза 0. Здесь зафиксированы инструменты, объяснено, зачем каждый нужен, почему
выбран, и кратко сравнён с аналогами. Это отправная точка — дальше по плану.

## Что такое RAG (напоминание)

RAG (Retrieval-Augmented Generation) — это когда мы **не** переобучаем модель, а
перед ответом **находим** релевантные куски документации и подкладываем их в
промпт. Пайплайн состоит из двух частей:

1. **Индексация (offline):** скачать доки → нарезать на чанки → посчитать
   эмбеддинги → сложить в векторную БД.
2. **Запрос (online):** вопрос → эмбеддинг → поиск похожих чанков → собрать
   контекст → LLM генерирует ответ со ссылками.

## Карта выбора

| Компонент | Выбор | Роль |
|-----------|-------|------|
| Источник данных | FastAPI docs | корпус для индексации |
| Векторная БД | Qdrant | хранит векторы + метаданные, ищет по близости |
| Runtime моделей | Ollama | запускает LLM и эмбеддинги локально |
| Модель эмбеддингов | `nomic-embed-text` | превращает текст в вектор |
| LLM | `qwen2.5:1.5b` | генерирует ответ по контексту |
| UI | Chainlit | чат-интерфейс в браузере |
| Оркестрация | podman-compose | поднимает всё одной командой |

## 1. Источник: документация FastAPI

**Зачем:** нужен реальный, но не гигантский корпус. FastAPI docs — структурированный
сайт с меню/заголовками, есть `sitemap.xml`. Хорош для быстрых итераций.

**Альтернативы:** Kubernetes docs (больше, ближе к проду), Docker docs (средний),
Python docs (огромный). Меняется одной строкой `DOCS_BASE_URL` + парсер.

## 2. Векторная БД: Qdrant

**Зачем:** хранит векторы чанков и умеет искать ближайшие. Даёт фильтры по
метаданным (`url`, `section`) и **web-дашборд** — новичку видно, что реально лежит
в базе.

**Почему Qdrant:**
- один контейнер, поднимается мгновенно;
- dashboard на `:6333/dashboard` — отличная наглядность для обучения;
- богатая фильтрация по метаданным + нативный **hybrid search** (пригодится на фазе 6);
- квантизация и хорошая память на больших объёмах (задел на рост);
- активная экосистема (LangChain/LlamaIndex-интеграции).

**Критерии выбора векторной БД:**

1. Режим развёртывания — embedded (библиотека) или отдельный сервер.
2. Фильтрация по метаданным вместе с ANN-поиском.
3. Hybrid search (dense + sparse/BM25) «из коробки».
4. Квантизация и потребление памяти.
5. Масштаб (тысячи vs миллионы+ векторов).
6. Экосистема и зрелость клиентов.
7. Ops: персистентность, бэкапы, HA, наличие UI.
8. Лицензия и стоимость.

**Сравнение:**

| БД | Плюсы | Минусы | Когда брать |
|----|-------|--------|-------------|
| **Qdrant** ⭐ | 1 контейнер, UI, фильтры, hybrid, быстрая (Rust) | чуть больше кода, чем Chroma | учиться + расти до прода |
| Chroma | очень просто, embedded | слабее фильтры/масштаб | прототип за 5 минут |
| pgvector | уже есть Postgres, SQL, транзакции | hybrid/квантизация слабее | данные уже в Postgres |
| Weaviate | модули, hybrid из коробки | тяжелее, «магии» больше | сложные схемы |
| Milvus | очень большой масштаб | тяжёлый стек (etcd, minio) | миллионы+ векторов |
| LanceDB | embedded, versioning | молодой | локальные датасеты без сервера |
| FAISS | чистый быстрый ANN | нет сервера, фильтров, персистентности | research/бенчмарки |
| Pinecone | managed, ноль ops | платно, наружу | не хочется self-host |

## 3. Runtime моделей: Ollama

**Зачем:** запускать LLM и модель эмбеддингов локально, без облака и API-ключей.
Умеет тянуть модели по имени одной командой (`ollama pull`).

**Почему Ollama:** простейший вход, готовый контейнер, OpenAI-совместимый API
(`/v1`), автоматическая загрузка GGUF-моделей. Идеально для обучения.

**Альтернативы:**

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Ollama** ⭐ | просто, контейнер, OpenAI API | меньше контроля над параметрами |
| llama.cpp | максимум контроля, легковесный | нужно собирать/конфигурировать |
| vLLM | лучшая пропускная способность на GPU | сложнее, рассчитан на GPU |
| LM Studio / text-gen-webui | GUI, удобно | не для compose/автоматизации |
| Облачный API (OpenAI/OpenRouter) | быстро, качественно | платно, данные наружу |

**Важно про железо (Ryzen AI 9 H 465, Radeon 880M + NPU):**
- **CPU (20 ядер):** работает сразу. Замер `qwen2.5:1.5b` — **~70 tok/s**
  (после прогрева), `nomic-embed-text` даёт вектор размерности **768**.
- **iGPU (gfx1150):** можно пробросить `--device /dev/dri`, но ROCm для этого
  чипа сырой. Потенциальная фаза 9.
- **NPU (XDNA2):** в контейнере ни Ollama, ни llama.cpp не используют. Пока мимо.

## 4. Модель эмбеддингов: `nomic-embed-text`

**Зачем:** превращает текст в вектор фиксированной длины (здесь 768), чтобы
сравнивать смысловую близость.

**Почему она:** хорошее качество для английских доков, размер ~274 МБ, поддержка
длинного контекста до 8192 токенов, идёт через Ollama — ещё один компонент не нужен.

**Альтернативы:** `all-minilm` (в разы быстрее, но ниже качество), `bge-m3`
(лучше и мультиязычно, тяжелее), `e5-*`, облачные `text-embedding-3-*`.
Для маленького корпуса разница в скорости не критична, поэтому берём качественную.

## 5. LLM: `qwen2.5:1.5b`

**Зачем:** генерирует финальный ответ, опираясь только на подложенный контекст.

**Почему она:** старт с самой лёгкой для скорости итераций, хорошо следует
инструкциям (instruct-версия), поддержка «отвечай только по контексту». Позже
переключимся на `qwen2.5:7b-instruct` для качества.

**Альтернативы:** `llama3.2:1b`/`3b`, `qwen3:0.6b`/`1.7b` (новее, есть режим
размышления), `gemma3:1b`, `phi3-mini`. Все меняются одной строкой `LLM_MODEL`.

## 6. UI: Chainlit

**Зачем:** готовый чат в браузере со стримингом, показом источников и
«шагов» рассуждения — ровно то, что нужно демонстрировать в RAG.

**Почему Chainlit:** заточен под LLM-приложения (в отличие от общих UI), минимум
кода, красивые элементы `Source`/`Step`.

**Альтернативы:** Streamlit (универсальнее, больше ручной работы), Gradio
(быстрый простой чат), FastAPI+htmx (максимум контроля, больше кода).

## 7. Оркестрация: podman-compose (через pipx)

**Зачем:** описывает все сервисы в одном `compose.yaml` и поднимает их одной
командой. На хосте уже есть Podman, но нет compose-провайдера.

**Почему так:** `pipx install podman-compose` изолирует инструмент и не мусорит
в системном Python. Альтернативы: бинарь `docker-compose` в
`~/.docker/cli-plugins` (надёжнее по фичам, но лишняя возня), `podman kube play`
(нативно, но сложнее для новичка).
